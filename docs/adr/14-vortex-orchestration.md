# 14 - Integration of VORTEX (Velocity Orchestration & Resource Thermodynamics EXecutive)

## Context and Problem Statement
Traditional AI orchestrations rely on conversational prompting, which often leads to the Sycophantic Attractor—where the AI produces flattened compromises when given complex or conflicting instructions. To function as a true Sovereign Cognitive Operating System (SCOS), AuthorForge AI needs a rigorous orchestration framework that inverts this dynamic. We must define how high-entropy human intent is clamped by deterministic machine scaffolding.

## Decision Drivers
*   The need to implement **Topological Layer Inversion** (base deterministic layers must be established before generative capabilities).
*   The requirement to replace conversational prompting with **Stigmergic Orchestration**.
*   The necessity of managing contradictory human inputs using Paraconsistent Logic (PAL2v) rather than boolean collapse.

## Considered Options
1.  Standard LangChain/ReAct agent looping.
2.  Conversational chat interfaces with hidden system prompts.
3.  **VORTEX-ARCHITECT Framework Integration:** Applying Negative Space Scaffolding to enforce rigid deterministic bounds on fluid AI generation.

## Decision Outcome
Chosen option: **VORTEX-ARCHITECT Framework Integration**.

We formally adopt the VORTEX principles for system orchestration.

### Positive Consequences
*   **Eradication of Projection Tax:** By using Draft-Conditioned Constrained Decoding (DCCD), we guarantee the structural validity of outputs (e.g., JSON schemas) before they are emitted, saving the human from syntax debugging.
*   **Fix Until Green Autonomy:** Establishes the foundational loop where code mutations are automatically subjected to linters, type checkers, and test suites until validation passes.
*   **Golden Scar Protocol Integration:** Allows the system to hold contradictory inputs in tension by applying the Golden Ratio ($\phi \approx 1.618$) to dominant epistemic frames, preventing sycophantic degradation.

### Negative Consequences
*   High initial friction for human operators accustomed to conversational "chat" models.
*   Requires rigorous definition of deterministic test layers (which currently represents a technical debt, as noted in ADR 11).

## Implementation Rules
*   All code-producing tasks MUST adhere to a strict TDD (Test-Driven Development) cycle.
*   The Golden Scar weightings must be explicitly logged and surfaced in the UI via the `CMDARefinementResult`.
